# Bar 1.1 体验与资源审计

目标：检查整体功能和布局，交付极简、低心智负担、资源占用小、使用丝滑的原生菜单栏工具。

以真实运行和可复测证据验收。2026-10-23：核心修复已安装，剩余桌面验收因电脑控制连接超时尚未完成；1.1 不作为新的正式公证版本发布。

## 验收项

- 主界面优先可管理图标；未运行和只读项目逐层展开。隐藏设置始终可恢复，不删除旧用户偏好。
- 显示开关无需学习眼睛按钮含义，搜索常驻，长名称/长反馈不挤出操作区。
- 未授权辅助功能时核心管理可用；说明按需展开，系统图标进入系统设置，不尝试写入。
- 应用启动/退出及时更新列表；关闭、重开、最小化、菜单栏点击、右键和快捷键保持原生行为。
- 快速重开不叠加扫描，关闭窗口不周期轮询；不在主线程进行偏好扫描和辅助功能 IPC。
- 未修改偏好只检查元数据，不反复读取/解析全部文件；缓存不改变目标覆盖或容器覆盖规则。
- 进程操作只正常退出，不强制结束；普通应用及拒绝退出应用有正确待生效反馈。
- 多图标/无位置记录不误借其他图标名称，不用“未能观察”证明“已生效”。
- 真实测试应用覆盖隐藏、恢复、退出后保留、普通应用待重启、取消重启、只读/多图标与自动列表更新。
- 资源以同一只读采样工具记录实际 CPU、physical footprint、RSS；静态窗口及关闭窗口都测量。目标空闲 CPU <0.3%、physical footprint <100 MiB，并披露测量条件。
- 源码回归、通用构建与实际应用运行均验证后再判断完成。

## 优化前证据

`1.0-before.png` 为正式版实际窗口；12 项回归测试在初轮调整后通过。
`1.0-visible-idle.json` / `1.0-hidden-idle.json` 使用 `Tools/measure-process.c` 采样。
原版空闲 CPU 已很低，不以移除定时器推导未经测量的节能比例。

## 已完成的修复与检查

- 主界面改为常驻搜索和显示开关，隐藏项目始终可恢复；未运行的可见项目默认折叠。长反馈限制两行，可关闭，权限说明放到按需面板。
- `⌘F` 定位搜索、`Esc` 清空、测试应用启动后自动进入列表，均通过实际界面操作验证。原来残留的已卸载测试应用不再挤占列表。
- 移除每 1.5 秒的循环检查。启动、窗口聚焦、唤醒和应用启动/退出事件合并触发扫描；关闭或最小化窗口时不发起新的周期扫描。
- 首次优化构建在真实容器文件的 `open` 中等待，虽然主线程响应正常，列表仍一直加载。修复后首次列表不读取容器；用户按需启动的容器读取通过自建短时辅助进程隔离，单文件三秒上限，并限制读取大小。该辅助进程的超时终止不涉及目标应用。
- 未变更偏好不再反复解析，缓存只保留菜单栏相关键；AX IPC 移出主线程，同时最多读取四个所属进程。图标缓存保留 48px 缩略图。
- 没有 AX 授权不再因“没有读到图标”而自动声明待重启；显式修改会记录待生效状态，保存 PID 与启动时间，跨 Bar 重启保留。
- 多图标位置不明确时使用应用和设置项名称，不借用另一个图标名称或推断状态。系统项目不写入，不重启 Control Center。
- `defaults` 写入和读回有三秒上限；所属应用只正常退出，拒绝退出时停止等待、保留进程并允许稍后处理。

## 真实测试应用

`Tools/build-audit-fixtures.py` 编译 `Tests/Fixtures/ExperienceFixture.swift`。测试应用的状态报告由实际 `NSStatusItem.isVisible` 产生，不用预设结果冒充系统状态。记录见 `runtime-fixtures.json`。

- 菜单栏工具：初始 PID 16690、实际可见；隐藏后 PID 17009、实际不可见；恢复后 PID 17044、实际可见。
- 普通应用：初始 PID 17151，修改后仍运行并显示“重新打开应用后生效”；确认重启后 PID 17176，实际不可见。
- 拒绝退出应用：请求正常重启后，原 PID 17870 保持运行，Bar 恢复操作并提示未能重启。“稍后”返回列表并保留待生效提示。退出并重新启动 Bar 后，该待生效记录仍在。
- 自建测试进程已结束，测试域可见性恢复为 true。未修改用户实际应用的可见性偏好，也未执行“全部显示”批量改变用户布局。

## 构建与资源

- 最终源码 `swift test --disable-sandbox`：15 项测试通过，包括缓存文件变更/新增/删除、Unicode plist、容器覆盖、初始扫描不读容器、系统写入拒绝、多图标歧义、并发上限及真实辅助进程超时。
- arm64 / x86_64 release 编译、`lipo -verify_arch` 通过，Developer ID 签名版本安装于 `/Applications/Bar.app`。此 1.1 构建尚未公证。
- 使用同一 `Tools/measure-process.c`，20 秒可见窗口采样为 CPU 0.0635%、physical footprint 50.673 MiB；最终构建 20 秒空闲采样 CPU 0.0013%、footprint 52.188 MiB。两次读写字节差为 0，详见 JSON。最后一次的窗口前后台状态未由截图重新确认。
- 原版 10 秒采样 CPU 已接近 0，不能据此声称节能提升比例。移除定时器是源码事实；此处不是跨机器续航评估，`idleWakeups` 也不等于所有线程唤醒。
- 只读偏好基准核对新旧发现的 35 个非 Apple 应用域一致：旧版后两次约 29–30ms，新缓存热扫描约 7.3–7.8ms，热扫描实际文件读取为 0。冷扫描受文件缓存影响，不能用首轮 234ms 与新扫描 22ms 宣称普遍加速比例。
